# Herdr Usage

**Layout.** One workspace per orchestrated run (unless the human explicitly requests another topology). **One tab per task**, named `<task> - <description>` (e.g. `t101 - routing refinement`). All sessions pertaining to that task open inside its tab and are named `<task>_<role>` (e.g. `t107_executor`, `t107_reviewer`, `t111_researcher`, `t105_interlocutor`). The orchestrator session is named `orchestrator`, or `orchestrator-<space>` when more than one space runs at once (`orchestrator-masking`, `orchestrator-tskctl`). One orchestrator belongs to each space, and that registered name — never a bare `orchestrator` assumed from another project — is the callback target used in every callback command. Completion wake-up goes through the relay (Callbacks in `.planning/orch/agents/ORCHESTRATOR_AGENT.md`); workers use exact marker forms.

**Relays.** A relay is a plain watch-only script (not a model, no tokens) that watches ONE delegated agent and, when that agent has settled AND its report exists, wakes the orchestrator. It then exits. Shared helpers live in `.planning/orch/relay-lib.sh` (`relay_log`, `relay_state`, `relay_is_gone`, `relay_blocked_label`, `relay_target`, `relay_fire`, `relay_fire_status`, `relay_settle`, `relay_emit_event`); `.planning/orch/relay-template.sh` is the starting point for a new relay. The library is repo-agnostic: it derives the repo root from its own location and names no project. Relays are written fresh to `$ORCH_RELAY_DIR/<TASK>-watch.sh` — by default `/tmp/orch/<repo>/relay/` — never derived from another relay, and never edited while running, because bash reads scripts incrementally. The control-plane target is never hardcoded either: `relay_target` resolves the single live agent matching `^orchestrator(-[a-z0-9]+)*$` whose cwd is this repo, so a relay in one space can never wake another space's orchestrator; `ORCH_TARGET` pins it explicitly, and an unresolvable or ambiguous target fails closed instead of firing at a guess. Re-arming a relay must never re-submit the task brief: a relay that re-sends the brief requeues the whole thing into the agent composer. The orchestrator owns the tsk board exactly as it owns the ledger, so a relay never writes the board itself: its event names the task (`TSK_ID`) and carries `ORCHESTRATOR_ACTION=update-tsk-board`, and the Orchestrator applies the status change after reading the report and judging the outcome.

**Lane state.** Relay scripts, the relay inbox, and run-command run folders are per repo, so two projects never share a `/tmp` namespace: `/tmp/orch/<repo>/{relay,relay-inbox,runs/run-command}`. `ORCH_HOME` relocates the whole root, the per-consumer `ORCH_RELAY_DIR` / `ORCH_EVENTS_DIR` / `RUN_COMMAND_RUNS_DIR` relocate one, and a one-line `.planning/orch/orch-home` file pins a repo to an existing location (that is how a project with state already under a legacy path stays there). The path convention is defined once, in the extension's `lib/orch-home.mjs`; the shell side mirrors it in `relay-lib.sh`. Keep the two in step: a relay that files its inbox event where the Orchestrator's inbox watcher is not looking fails silently.

**The dispatch extension.** `orch_dispatch` / `orch_status` / `orch_stop` are documented in full — purpose, flow, every parameter, refusals, the relay's state machine, and diagrams — at `~/.pi/agent/extensions/orch-dispatch.md`. The extension itself is `~/.pi/agent/extensions/orch-dispatch.ts` with its siblings under `~/.pi/agent/extensions/lib/`; it is loaded globally, not per repo.

**Tab hygiene.** Unused sessions are closed as soon as their work ends — no idle tabs accumulating across tasks. An agent exists only while its task or process needs it: when that task or process is completed, the agent is killed/quit immediately — never left idle. A session that will be reused inside a loop (consecutive checkpoints of one executor, rounds of one dialogue, one deliberation item) stays open until that loop or assignment is completed, then is killed/quit. A task tab is closed when its task is settled and no session inside it remains active. The workspace ends each run with only the `orchestrator` session and the tabs of still-active tasks. Every tab is named after its task — never leave a tab untitled or carrying a stale name after a retarget. Periodically sweep dead tabs (empty, errored, or superseded by a replacement session); a replacement dispatch never inherits the old tab. Session cleanup is manual: Herdr has no prune or quit subcommand — send `/quit` with `herdr pane run <pane> /quit` (text and Enter in one call), verify the agent is GONE, then `herdr pane close <pane>`. Never close a pane whose agent is still working. The older two-step form (`herdr pane send-text` then `herdr pane send-keys <pane> Enter`) silently stopped submitting after the Herdr 0.9 upgrade — the text lands in the composer but never runs, so a sweep can appear to succeed while changing nothing. Confirm the agent is actually GONE rather than trusting that the quit was delivered.

**A hygiene sweep covers four levels, not one.** Quitting agents and closing their panes is only the first step; a sweep that stops there leaves the rest of the mess behind, and each remaining level has its own failure mode.

1. **Agents.** `/quit` + verify GONE, then close the pane (above).
2. **Tabs.** Closing a pane does NOT remove its tab, so every retired agent leaves an empty tab unless the tab is closed explicitly: `herdr tab close <tab_id>`. Sweep with `herdr tab list` and require that only the orchestrator tab and the tabs of still-active tasks remain. Close the tab of every settled task whose sessions are all gone.
3. **Workspaces.** Check `herdr workspace list`; the run's workspace should end with only live-task tabs. Never touch a workspace belonging to another project.
4. **Processes and stranded artifacts.** Kill relays whose watched agent is already gone — a live relay pointed at a retired agent will fire a FALSE completion event at the orchestrator (this has happened, so it is not hypothetical). Then check every finished worktree for untracked files, especially evidence reports: a report written inside a lane's worktree never reaches main by itself, so collect it into `.planning/` explicitly. Finally `git worktree prune` for entries whose directories are already gone.

Before closing panes or tabs, confirm they are actually yours to close: layout panes are not leftovers. Panes carrying a `label` such as the `tsk` plugin pane or `Sidebar` panes are part of the human's setup, and another project's workspace is never in scope.

**Artifact disposal.** Executors create files only within owned paths, including any expressly authorized temporary path. Disposable tooling there is deleted before the report and disclosed in it. Artifacts outside owned paths are reported and left untouched unless separately authorized.
